## Test Strategy

Test by component wave, preserving behavior before each deeper integration step. Because this is a user-visible canvas feature, final acceptance requires a targeted Playwright smoke in addition to unit/integration tests.

## Component Test Matrix

### C1 — Node Contract Model / Bridge

- Input node with one required text field derives an effective input contract field.
- Input node with text + image fields derives a grouped effective input model.
- Multiple Input nodes derive deterministic field order.
- Output Extractor node derives artifact definition.
- Legacy workflow with `inputContract` and no Input nodes still returns legacy input fields.
- When Input nodes exist, node-derived inputs are primary over stale `inputContract`.
- Invalid node/field keys are rejected or normalized consistently.

### C2 — Canvas Node Types and Palette

- `SwarmCanvas` renders Input node and Output Extractor node.
- `NodePalette` shows Input and Output Extractor cards.
- Drag/drop or add helper creates default node data.
- Node visual summary shows label/type/field count.

### C3 — Inspector Configuration UX

- Selecting Input node shows Input configuration fields.
- Add/remove fields updates node data.
- Field types work: text, textarea/markdown, JSON, enum, number/integer, boolean, image.
- Selecting Output Extractor shows artifact name/format/instruction fields.
- Selecting Agent allows editing expected output.
- Settings Interface is hidden/deprecated/read-only as chosen.

### C4 — Run Form and Image Input Handling

- Run modal groups fields by Input node.
- Required text field blocks submit when empty.
- Image field renders upload/control.
- Text + image submit returns structured payload with image metadata/reference.
- Legacy `inputContract` still renders when no Input nodes exist.
- Server accepts valid text+image metadata and rejects oversized/invalid/unsafe image input.

### C5 — Runtime Prompt Injection and Handoff Semantics

- Agent connected to Input receives labeled input block in prompt.
- Agent not connected to Input does not receive it by default.
- Agent expected output appears for that agent only.
- Downstream handoff includes upstream output label/contract when configured.
- Legacy workflow prompt behavior remains when no visual I/O nodes exist.

### C6 — Output Extractor and Artifact Pipeline

- One Output Extractor connected to one agent produces one artifact.
- Artifact key/name/format match node config.
- Missing upstream output produces empty/error artifact status, not crash.
- Multiple extractors produce multiple artifacts deterministically.
- Store/UI hydrates and displays extractor-produced artifact.

### C7 — Compatibility, Migration, Pack-Ready Shape

- Existing saved workflow with contracts loads without crash.
- Import/export roundtrip preserves new Input/Output Extractor nodes.
- Save/load preserves bridge fields when generated.
- Pack-related tests do not regress if pack surfaces are touched.

### C8 — Validation and E2E

- Required Input node with no fields warns.
- Input node with invalid key warns.
- Output Extractor with no incoming edge warns.
- Output Extractor missing artifact key/name/format warns.

## Architect-Driven Test Additions

### Graph Execution Semantics Tests

- Start-agent detection ignores incoming `input -> agent` edges.
- Runtime does not schedule/spawn `input` nodes.
- Runtime does not schedule/spawn `outputExtractor` nodes.
- Validation accepts `input -> agent` and `agent -> outputExtractor`.
- Validation rejects or warns on `outputExtractor -> agent`, `input -> input`, and `input -> outputExtractor`.

### Effective Schema Tests

- `InputNode.data.fields[].type = image` normalizes and validates.
- Image value shape requires `assetId`, `name`, `mimeType`, and `size`.
- `OutputExtractorNode.data.format = table` is accepted in node schema.
- `table` artifact serializes safely for current renderer if dedicated table renderer is absent.
- Legacy `data.expectedOutput` maps/falls back to `expectedOutputContract.instructions`.

### Run Asset Upload Boundary Tests

- Upload route, if implemented, requires mutating request protections.
- Reject unsupported MIME type.
- Reject oversized image.
- Reject traversal filename/path.
- Uploaded image returns run-scoped asset metadata/reference.
- Prompt payload contains asset metadata/reference, not raw base64 by default.
- If upload route is not implemented, image execution fails with explicit validation instead of silent drop.

### Output Extractor Resolution Tests

- `firstIncoming` uses deterministic workflow edge order.
- `allIncoming` includes all upstream outputs with labels.
- `selected` validates selected source IDs.
- Missing upstream output yields `empty` or `error` artifact status.
- Extractor never falls back silently to unrelated aggregate final text.
- Artifact result includes extractor provenance when possible.

### Settings Source-of-Truth Tests

- Workflow with visual I/O nodes shows Settings Interface as read-only/advanced summary, not editable source.
- Legacy workflow with no visual I/O nodes can still use legacy contract fallback.
- Editing visual nodes updates effective contracts used by run form.
- Stale legacy contract fields do not override node-backed inputs when Input nodes exist.

## Per-Element Relationship Test Rule

At the end of every implemented element, test its relationship to the current system with a concrete target outcome:

- New helper -> compare against legacy contract behavior.
- New node -> verify existing nodes still work.
- New inspector field -> verify existing agent fields still persist.
- New run form field -> verify old run form still works.
- New runtime injection -> verify old prompt path still works.
- New extractor artifact -> verify old artifacts still display.
- New compatibility path -> verify old imports/exports still roundtrip.

A generic “manual check passed” is not enough. The expected result must name the old behavior being protected and the new behavior being proven.

## Canonical Gate Policy — Supersedes Earlier Generic Wording

For every microwave, both client and server impact must be classified as one of:

- **Direct test:** layer changed or directly affected; create/extend/run the named tests and they must pass.
- **Substitute regression:** layer not directly changed but integration can regress; run the named nearby regression and it must pass.
- **N/A with rationale:** no meaningful relationship exists; record rationale.

A microwave may proceed only when all Direct/Substitute tests pass and N/A rationales are recorded.

### Baseline Gate Policy

- Affected baseline tests must pass before Wave 1.
- If affected baseline tests fail, create/fix a baseline-stabilization microwave before feature work unless the failure is proven unrelated and recorded as pre-existing.
- No wave may introduce new failures relative to the recorded baseline.
- Any pre-existing exception must include command, failing test name, suspected owner, and why it does not invalidate the next wave.

### Automation-first Current-System Relationship Rule

Current-system relationship tests must be automated whenever reachable through existing unit/integration/E2E harnesses. Manual checks are allowed only for visual inspection gaps and must include exact steps, observed result, and why automation was not practical.
